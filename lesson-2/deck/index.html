Кажется, вопросы дурацкие? Это пробелы в задаче. Всё из головы собирается, если пройти по шагам

Ответ на главную жалобу: «бот задаёт примитивные вопросы». Восемь шагов интервью — это и есть структура любой задачи: чёткий старт (с каких документов и запроса, какие вводные, какие инструменты и доступ) и чёткий финал (что получить на выходе), между ними порядок действий и проверки. Цифры из базы: четыре пакета, по 33–35 ответов, от получаса до часа без перерывов; у дошедших по одному «не указано», у застрявшего на последнем шаге — пять. → — цифры. Пятая строка — про рамки: бот собирает ТЗ на одну вашу рабочую задачу, которую вы делаете руками; просьбы «сделай мне бота», «придумай за меня», «найди статистику» он по сценарию отклоняет и возвращает к одному шагу. Это не глупость модели (в диалоге работает Sonnet, документы пишет Opus): скрипт из восьми карточек держит модель в рамках, и рамки нужно проектировать так же тщательно, как и промпт. Рамки стояли нарочно: простая задача, которую легко описать. → — вывод: если вопрос кажется дурацким, это пробел в постановке; всё, что в голове, собирается, если разложить по шагам.

Развилка на одной задаче. Верхняя ветка — её ТЗ как есть: бот работает в рамках названных инструментов, а всё, во что они упираются, закрывается руками: переслать, снять экран, отправить шефу. Три действия руками. Нижняя ветка — что меняется, если на первом же «упёрлись» открыть новый чат и спросить «какие ещё есть инструменты и подходы»: агент предложит Telegram‑бота вместо WhatsApp, робот‑браузер через прокси, кэш цен Aviasales по API как ориентир (готовых API живых цен частному лицу нет — проверено); модель читает страницы, варианты приходят в Telegram. Это проект, его не прогоняли, условия ТЗ меняются и согласуются с руководителем. → — верхняя ветка: как бот собрал ТЗ по словам участника: WhatsApp, ручная пересылка, агрегаторы, снимки с телефона, три действия руками. → — нижняя ветка: как тот же процесс собирается с опытом: Telegram‑бот вместо WhatsApp, робот‑браузер по сайтам авиакомпаний через прокси, API для поиска живых цен частному лицу практически недоступны: Amadeus Self‑Service закрыт 17.07.2026, Kayak и Skyscanner дают API только партнёрам, Travelpayouts/Aviasales отдаёт кэш цен 2–7 дней, живой поиск — от 50 000 посетителей в месяц. Поэтому робот‑браузер и прокси, а кэш Aviasales только как ориентир; страницы читает модель — руками ничего. Нижняя ветка — проект решения, его не прогоняли; верхняя — то, что записано в ТЗ. → — вывод: бот знает только то, что ему сказали; опыт добавляется одной задачей агенту «придумай процесс без ручных действий».

Три правила, каждый → — следующее. По закону 152‑ФЗ передача персональных данных иностранному сервису — трансграничная передача: нужны уведомление Роскомнадзора и основание (согласие), поэтому правило 01 — не отправлять ПДн в облако без решения руководства и ИТ. YandexGPT и GigaChat работают на серверах в России, но что они хранят и как — смотреть в их договоре (у Yandex логирование запросов отключается заголовком). Третье — развилка: данные можно отдавать — подключаем облако (Claude, Codex, OpenRouter, любая модель); нельзя — своя модель на сервере, как в ГСП. Справа кабинет ГСП‑помощника.

Сначала четыре файла пакета, затем каждый → — один из трёх путей. Путь «папка и агент» для новичка: поставить Claude Code, войти по подписке, открыть папку с пакетом, написать «работай по ТЗ». Путь «бот»: токен от BotFather и ключ в чат агенту не вставлять — он создаёт .env.example, значения вписываете сами, .env не попадает в Git. Для тех, у кого пакета нет (таких большинство): возьмите восемь разделов слайда 3, опишите вход и выход своей задачи и попросите агента задать недостающие вопросы — это и есть ТЗ. В конце: не сошлось — результат не принимаем; показываем агенту ожидаемое и полученное и просим найти причину по ТЗ. Требования меняем только если ошиблись в них, иначе исправляем исполнение. Главный посыл второй половины: не бояться спрашивать. Первый вопрос — про инструменты: упёрлись в блокировку, в закрытый мессенджер, в «не получается» — откройте новый чат, опишите, во что упёрлись, и спросите, какие ещё есть инструменты и подходы; агент накидает варианты (так родилась нижняя ветка на слайде про рейсы). Дальше непонятное — сервер, ключ API, куда переходить — тот же приём: новый чат, пошаговая инструкция под вашу задачу. → — оборотная сторона: агент мыслит прямо. Когда он собирает бота или приложение, кажется, что все моменты проработаны, но это не так: он не скажет сам, какие ключи и доступы нужны с вашей стороны. Поэтому спрашивать заранее («что нужно от меня, чтобы это заработало?»), смотреть план реализации своими глазами и понимать главную мысль задачи. Пример — рейсы: бот написал процесс по словам участника, опыт добавился вопросом агенту.

Чеклист настройки, по порядку. Машина, которая работает всегда: домашний компьютер (как у меня), Mac mini или арендованный сервер; выбор по бюджету. Аккаунты: один Google‑аккаунт, через него входите везде, где есть «войти через Google» (OpenRouter в том числе); GitHub для кода и истории; Telegram и токен от BotFather для бота.
